## 1. 存储选型

| 程序 | 存储 | 说明 |
|---|---|---|
| seeinpm | **SQLite**（内嵌，`data/seeinpm.db`） | 单机部署、量级适中，零依赖；表结构见 §3；预留迁移 PostgreSQL/MySQL 的适配层 |
| seeinps | **SQLite**（内嵌，`data/seeinps.db`） | 本地代理配置、本地用户、流量缓存 |
| seeinpc | JSON 配置文件 | `conf/config.json`（多 VPN profile），密码字段 DPAPI 加密 |

> 各程序数据文件位于安装目录 `data/`（程序文件层级见 05-project.config.md）。

---

## 2. 通用约定

| 项 | 约定 |
|---|---|
| 主键 | 所有表使用 `INTEGER PRIMARY KEY AUTOINCREMENT`（业务唯一键另建唯一索引） |
| 时间 | 全部存 **UTC Unix 时间戳（INTEGER，秒）**；展示层转本地时区；B端标注时区 |
| 软删除 | 用户/代理采用 `status` 字段而非物理删除；审计/连接/流量数据**只增不删**（按保留策略清理） |
| 外键 | 启用 `PRAGMA foreign_keys = ON` |
| 事务 | 写操作显式事务；跨表一致性操作（分配端口+建代理）单事务提交 |
| Schema 版本 | 表 `schema_meta(version)`，启动时迁移（§6） |
| 写策略 | 高频写入（流量统计）采用**批量提交 + WAL 模式**，防磁盘 IO 瓶颈 |
| 并发 | SQLite WAL + busy_timeout=5000；单写者多读者 |

## 3. seeinpm 表设计（`data/seeinpm.db`）

### 3.1 用户与授权码

```sql
CREATE TABLE users (
  id            INTEGER PRIMARY KEY AUTOINCREMENT,
  username      TEXT    NOT NULL UNIQUE,          -- 登录用户名（seeinps 部署时填写的用户名）
  remark        TEXT,                             -- 备注（非必填）
  group_id      INTEGER REFERENCES groups(id),    -- 分组
  port_range    TEXT,                             -- 可用端口区间，如 "20000-25000,26000"；NULL=全池随机
  status        INTEGER NOT NULL DEFAULT 1,       -- 1=启用 0=禁用（禁用=拒绝新注册+可选断连）
  auth_code     TEXT    NOT NULL,                 -- 授权码哈希（bcrypt(sha256(salt+code))）
  auth_code_salt TEXT   NOT NULL,                 -- 每次生成授权码的随机盐
  auth_code_updated_at INTEGER,                   -- 授权码最近重置时间
  online_session TEXT,                            -- 当前在线会话 ID（NULL=离线）→ 单实例判定依据
  online_since  INTEGER,                          -- 本实例在线起始时间
  created_at    INTEGER NOT NULL,
  updated_at    INTEGER NOT NULL
);
CREATE UNIQUE INDEX ux_users_auth_code ON users(auth_code);

-- 分组
CREATE TABLE groups (
  id         INTEGER PRIMARY KEY AUTOINCREMENT,
  name       TEXT NOT NULL UNIQUE,
  created_at INTEGER NOT NULL
);
```

> 授权码唯一性由 `auth_code` 唯一索引 + 业务层保证；**单实例绑定**由 `online_session` 字段维护：注册时若 `online_session` 非空且对应心跳未超时 → 拒绝（协议码 1002）；心跳超时判定离线后允许新会话覆盖。

### 3.2 端口池与端口分配

```sql
CREATE TABLE port_pool_ranges (              -- 端口池配置（可多区间）
  id         INTEGER PRIMARY KEY AUTOINCREMENT,
  start_port INTEGER NOT NULL,
  end_port   INTEGER NOT NULL,
  excluded   TEXT,                            -- 排除端口，如 "20001,20005-20010"；JSON 数组
  created_at INTEGER NOT NULL
);

CREATE TABLE port_allocations (              -- 端口分配记录（重启恢复依据）
  id            INTEGER PRIMARY KEY AUTOINCREMENT,
  port          INTEGER NOT NULL UNIQUE,
  user_id       INTEGER NOT NULL REFERENCES users(id),
  proxy_id      TEXT    NOT NULL UNIQUE,      -- 代理 ID（对应 proxies.proxy_id）
  alloc_type    TEXT    NOT NULL,             -- tcp / udp / ops_http / ops_socks
  status        INTEGER NOT NULL DEFAULT 1,   -- 1=在用 0=已释放
  allocated_at  INTEGER NOT NULL,
  released_at   INTEGER
);
CREATE INDEX ix_alloc_user ON port_allocations(user_id, status);
```

**分配算法**（`ALLOC_PORT` 服务端处理，需求文档 §6）：
1. 目标端口 = 请求指定端口 或 用户限制区间内随机 或 全池随机；
2. 校验：`port_allocations` 无冲突（status=1）且系统可监听（`net.Listen` 探测，防系统端口占用）；
3. 事务内：插入 `port_allocations` + 更新 `proxies` → 提交；
4. 失败原因映射：冲突→3001、池耗尽→3002、超区间→3003。

### 3.3 代理

```sql
CREATE TABLE proxies (
  id            INTEGER PRIMARY KEY AUTOINCREMENT,
  proxy_id      TEXT    NOT NULL UNIQUE,       -- 全局代理 ID（协议用，如 px-9b2f）
  user_id       INTEGER NOT NULL REFERENCES users(id),
  type          TEXT    NOT NULL,              -- tcp / udp / ops_http / ops_socks
  name          TEXT    NOT NULL,
  local_addr    TEXT,                          -- 内网目标地址（tcp/udp：127.0.0.1:3306）
  public_port   INTEGER,                       -- 对外端口（= 运维ID，ops 类型对用户展示）
  acl           TEXT,                          -- ops 类型 ACL 配置（JSON：白名单/黑名单网段）
  bandwidth_limit INTEGER DEFAULT 0,           -- 带宽上限 B/s；0=不限
  max_conns     INTEGER DEFAULT 0,             -- 并发上限；0=不限
  status        INTEGER NOT NULL DEFAULT 1,    -- 1=启用 0=禁用 2=故障
  created_at    INTEGER NOT NULL,
  updated_at    INTEGER NOT NULL
);
CREATE INDEX ix_proxies_user ON proxies(user_id, status);
```

> **注意**：ops 代理的「代理用户名/密码」**不存储在本表**（仅 seeinps 本地，见 §4）。seeinpm 只存 `acl`、限流参数等非敏感配置。

#### 3.3.1 当前已实现子集【已实现】

实现版代理表以 `(username, proxy_id)` 唯一标识（seeinps 用户名 + seeinps 本地代理 ID），记录在线状态与累计流量：

```sql
CREATE TABLE proxies (
  id              INTEGER PRIMARY KEY AUTOINCREMENT,
  username        TEXT    NOT NULL,            -- 归属 seeinps 用户
  proxy_id        TEXT    NOT NULL,            -- seeinps 上配置的代理 ID
  proxy_type      TEXT    NOT NULL DEFAULT '', -- tcp / udp / ops_http / ops_socks
  status          INTEGER NOT NULL DEFAULT 1,  -- 1=启用 0=禁用（手动；禁用永不自动清理）
  online          INTEGER NOT NULL DEFAULT 0,  -- 1=当前在线（公网监听已建立）
  last_online_at  INTEGER,                     -- 最近一次连接（上线）时间
  last_offline_at INTEGER,                     -- 最近一次离线时间
  bytes_in        INTEGER NOT NULL DEFAULT 0,  -- 累计入站字节（外部→内网）
  bytes_out       INTEGER NOT NULL DEFAULT 0,  -- 累计出站字节（内网→外部）
  created_at      INTEGER NOT NULL,
  updated_at      INTEGER NOT NULL,
  UNIQUE(username, proxy_id)
);

CREATE TABLE proxy_sessions (                  -- 代理每次在线的会话记录（上线→离线）
  id          INTEGER PRIMARY KEY AUTOINCREMENT,
  username    TEXT    NOT NULL,
  proxy_id    TEXT    NOT NULL,
  online_at   INTEGER NOT NULL,                -- 连接时间
  offline_at  INTEGER,                         -- 离线时间（NULL=当前在线）
  remote_addr TEXT    NOT NULL DEFAULT ''      -- seeinps 来源地址
);
CREATE INDEX idx_proxy_sessions_proxy ON proxy_sessions(username, proxy_id, id DESC);
```

- 上线：`ALLOC_PORT` 成功后 upsert 代理记录并开启一条会话（未关闭会话不重复开）；离线：`RELEASE_PORT`、seeinps 断连、清理例程回收端口时置离线并关闭会话；
- 流量在 seeinpm 转发处统计，内存计数 60s 周期落库（离线/关停时即时落库），接口返回总量 = DB 累计 + 未落库增量；
- 每代理会话历史最多保留 50 条；每小时清理离线超 7 天且未禁用（status=1）的代理及其会话，代理重连时自动重建记录。

### 3.4 连接记录（访问日志落库）

```sql
CREATE TABLE connections (
  id         INTEGER PRIMARY KEY AUTOINCREMENT,
  conn_id    TEXT    NOT NULL UNIQUE,          -- 协议 CONN_EVENT 的 connId
  proxy_id   TEXT    NOT NULL REFERENCES proxies(proxy_id),
  user_id    INTEGER NOT NULL REFERENCES users(id),
  event      TEXT    NOT NULL,                 -- open / close / auth_fail
  client_ip  TEXT,                             -- 来源 IP（seeinpc 侧公网 IP）
  target     TEXT,                             -- 目标地址（脱敏处理敏感端口策略？可配置）
  auth_ok    INTEGER,                          -- 认证是否通过（ops 类型）
  rx_bytes   INTEGER DEFAULT 0,
  tx_bytes   INTEGER DEFAULT 0,
  opened_at  INTEGER,
  closed_at  INTEGER,                          -- 断开时间（历史记录核心字段）
  close_reason TEXT                            -- 主动/超时/异常/管理断开
);
CREATE INDEX ix_conn_proxy ON connections(proxy_id, closed_at);
CREATE INDEX ix_conn_user  ON connections(user_id, closed_at);
```

### 3.5 流量统计（分钟级原始 + 聚合）

```sql
CREATE TABLE traffic_minutes (                 -- 原始分钟级（保留 7 天）
  bucket    INTEGER NOT NULL,                  -- 分钟桶：unix(分钟) = ts / 60
  proxy_id  TEXT    NOT NULL REFERENCES proxies(proxy_id),
  user_id   INTEGER NOT NULL REFERENCES users(id),
  rx_bytes  INTEGER NOT NULL DEFAULT 0,
  tx_bytes  INTEGER NOT NULL DEFAULT 0,
  conn_count INTEGER NOT NULL DEFAULT 0,
  PRIMARY KEY (bucket, proxy_id)
);

CREATE TABLE traffic_hours (                   -- 小时聚合（保留 90 天）
  bucket    INTEGER NOT NULL,                  -- unix(小时)
  proxy_id  TEXT    NOT NULL,
  user_id   INTEGER NOT NULL,
  rx_bytes  INTEGER NOT NULL DEFAULT 0,
  tx_bytes  INTEGER NOT NULL DEFAULT 0,
  PRIMARY KEY (bucket, proxy_id)
);

CREATE TABLE traffic_days (                    -- 天聚合（保留 365 天）
  bucket    INTEGER NOT NULL,                  -- unix(天)
  user_id   INTEGER NOT NULL,
  rx_bytes  INTEGER NOT NULL DEFAULT 0,
  tx_bytes  INTEGER NOT NULL DEFAULT 0,
  PRIMARY KEY (bucket, user_id)
);
```

### 3.6 审计日志

```sql
CREATE TABLE audit_logs (
  id         INTEGER PRIMARY KEY AUTOINCREMENT,
  action     TEXT NOT NULL,                    -- user.create / authcode.reset / portpool.update / proxy.delete / version.upload / login.fail ...
  operator   TEXT NOT NULL,                    -- 操作人（管理员用户名 或 "system"）
  operator_ip TEXT,                            -- 来源 IP
  detail     TEXT,                             -- JSON 详情（脱敏：不含密码/授权码明文）
  result     INTEGER NOT NULL,                 -- 0=成功 1=失败
  created_at INTEGER NOT NULL
);
CREATE INDEX ix_audit_created ON audit_logs(created_at);
CREATE INDEX ix_audit_operator ON audit_logs(operator, created_at);
```

### 3.7 版本管理（versions 表）

存储 seeinpm / seeinps / seeinpc 三端发布的版本元数据（对应需求文档 §4.5、API 规范 §2.7）。安装包文件落盘于 `data/releases/{endpoint}/`（目录结构见 05-project.config.md），表只存元数据。

```sql
CREATE TABLE versions (
  id           INTEGER PRIMARY KEY AUTOINCREMENT,
  endpoint     TEXT    NOT NULL,               -- seeinpm / seeinps / seeinpc
  version      TEXT    NOT NULL,               -- SemVer，如 1.2.0
  url          TEXT    NOT NULL,               -- 下载地址：/releases/{endpoint}/<filename>
  sha256       TEXT    NOT NULL,               -- 安装包 SHA256（服务端计算）
  release_note TEXT,                           -- 更新说明（多行文本）
  released_at  INTEGER NOT NULL,              -- 发布时间（UTC Unix 秒）
  uploaded_by  TEXT,                           -- 发布人（平台管理员用户名）
  created_at   INTEGER NOT NULL
);
CREATE UNIQUE INDEX ux_versions_endpoint_version ON versions(endpoint, version);  -- 同端同版本号唯一，禁止覆盖
CREATE INDEX ix_versions_endpoint ON versions(endpoint, released_at);
```

> **写入策略**：每次上传插入新行；同端同版本号已存在则返回 `3006 版本已存在`（沿用 3xxx 资源冲突段，可在 03 文档错误码段补充）。版本号校验 SemVer 格式（`^\d+\.\d+\.\d+`）。
>
> **「不再提醒」状态不存于此**：服务端只负责发布版本，**不存储**任何客户端的忽略状态；忽略状态完全由客户端本地持久化（见 §8）。

## 4. seeinps 表设计（`data/seeinps.db`）

```sql
-- 本地用户（管理页登录；密码仅存本地，绝不上传）
CREATE TABLE local_users (
  id            INTEGER PRIMARY KEY AUTOINCREMENT,
  username      TEXT NOT NULL UNIQUE,          -- = seeinpm 用户名
  password_hash TEXT NOT NULL,                 -- bcrypt（管理页密码）
  must_change   INTEGER NOT NULL DEFAULT 1,    -- 首次登录强制改密标记（需求文档 §5.4）
  created_at    INTEGER NOT NULL,
  updated_at    INTEGER NOT NULL
);

-- 本地代理配置（与 seeinpm 侧 proxies 对应；仅本地项存于此）
CREATE TABLE local_proxies (
  id             INTEGER PRIMARY KEY AUTOINCREMENT,
  proxy_id       TEXT NOT NULL UNIQUE,         -- 与 seeinpm proxies.proxy_id 一致
  type           TEXT NOT NULL,
  name           TEXT NOT NULL,
  local_addr     TEXT,                         -- 内网目标
  public_port    INTEGER,                      -- seeinpm 分配（= 运维ID）
  proxy_username TEXT,                         -- 运维代理账号（ops 类型）
  proxy_password TEXT NOT NULL,                -- 运维代理密码（bcrypt，仅本地）
  acl            TEXT,                         -- ACL JSON（与 seeinpm 一致）
  bandwidth_limit INTEGER DEFAULT 0,
  max_conns      INTEGER DEFAULT 0,
  status         INTEGER NOT NULL DEFAULT 1,
  created_at     INTEGER NOT NULL,
  updated_at     INTEGER NOT NULL
);

-- 本地流量缓存（先写本地，周期/事件上报 seeinpm 后清理已确认数据）
CREATE TABLE local_traffic_cache (
  id        INTEGER PRIMARY KEY AUTOINCREMENT,
  proxy_id  TEXT NOT NULL,
  bucket    INTEGER NOT NULL,                  -- 分钟桶
  rx_bytes  INTEGER NOT NULL DEFAULT 0,
  tx_bytes  INTEGER NOT NULL DEFAULT 0,
  reported  INTEGER NOT NULL DEFAULT 0         -- 0=未上报 1=已上报待清理
);

-- 本地审计（B端操作）
CREATE TABLE local_audit_logs (
  id         INTEGER PRIMARY KEY AUTOINCREMENT,
  action     TEXT NOT NULL,
  operator   TEXT NOT NULL,
  operator_ip TEXT,
  detail     TEXT,
  created_at INTEGER NOT NULL
);
```

## 5. 流量统计采集与聚合策略

| 层 | 粒度 | 来源 | 保留 | 说明 |
|---|---|---|---|---|
| 原始 | 分钟 | seeinps 本地缓存 → 上报 seeinpm | 7 天 | seeinps 每 15s 累计计数；上报后标记，清理任务删除已上报且超 24h 的行 |
| 聚合-小时 | 小时 | seeinpm 定时任务（每整点，对分钟表聚合） | 90 天 | 按 (proxy_id, bucket) 聚合 |
| 聚合-天 | 天 | 每天 00:05 对小时表聚合 | 365 天 | 按 user_id 聚合（用户级账单/总览） |
| 展示 | — | B端按需取层 | — | 近 24h 用分钟表、近 90 天用小时表、更早用天表 |

- 聚合任务幂等（bucket 主键 upsert），失败自动补跑；
- seeinpm 启动时检查是否有漏聚合 bucket 并补齐；
- 清理任务每日执行：删除超期分钟/小时行；
- 时间依赖 NTP：部署要求同步系统时间（文档与部署工具均提示）。

## 6. Schema 版本与迁移

| 项 | 说明 |
|---|---|
| 版本表 | `schema_meta(version INTEGER)`，初始 1 |
| 迁移机制 | 启动时读取版本号，按序执行 `migrations/00X.sql`（随程序分发在 `script/` 或内嵌），每个迁移在事务内执行并更新版本号 |
| 原则 | 只允许向前迁移；升级前自动备份（见 §7） |
| 兼容 | 新版本程序可读旧 Schema（降级路径：官方不承诺降级，通过备份恢复） |

---

## 7. 备份与恢复

| 项 | 说明 |
|---|---|
| 自动备份 | 每次升级/迁移前自动备份 `data/seeinpm.db` → `data/backup/seeinpm-<version>-<ts>.db`（SQLite 在线备份 API，保证一致性） |
| 手动备份 | B端「系统管理-备份」触发；保留最近 10 份 |
| 一键恢复 | 停止服务 → 替换 db 文件 → 启动；B端提供恢复指引（恢复后端口分配/在线状态按库内数据恢复） |
| 备份验证 | 备份完成后执行 `PRAGMA integrity_check` 并记录结果（需求：备份验证功能） |
| 配置备份 | `conf/` 配置文件随部署工具支持导出/导入（需求文档 F-S7） |

## 8. 客户端本地存储（版本忽略状态）

「该版本不再提醒」状态由客户端本地持久化，**服务端不记录**（versions 表只存版本发布元数据，见 §3.7）。各端存储位置：

| 端 | 存储位置 | 键/字段 | 值结构 | 说明 |
|---|---|---|---|---|
| seeinps（B端 Web） | 浏览器 localStorage | `seeinp:ignored-versions` | `{"seeinps":["1.1.0"],"seeinpc":["2.0.1"]}` | seeinps 仪表板在调用 `/api/v1/version/check` 后，若返回的 `latest.version` 存于此列表则不弹窗；提供「已忽略版本」入口可手动清除后重新提醒 |
| seeinpc | 本地配置文件 `conf/config.json` | `ignoredVersions` | `["2.0.1"]`（字符串数组） | seeinpc 启动检查升级后，若用户勾选「该版本不再提醒」则把版本号追加到此数组；高于已忽略所有版本的新版本发布时重新提醒 |

**客户端判断逻辑**：调用 `/api/v1/version/check`（见 03 文档 §2.7）得到 `latest.version` → 若该版本在本地忽略列表中则静默不提醒 → 当 `latest.version` 严格大于忽略列表中所有版本（SemVer 比较）时重新弹出提醒。

> seeinps 端因 B 端是 Web，使用 localStorage；seeinpc 端是桌面程序，使用本地配置文件。两端均不向服务端上报忽略状态。
