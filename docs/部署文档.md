# seeinp 部署文档

> 本文档详细说明 seeinp 三端（seeinpm 中心端 / seeinps 服务端 / seeinpc 客户端）的独立安装、配置与运行步骤。
> 适用于 v0.1.0 及以上版本。

---

## 最终成果物下载

> 无需自行编译源码，直接从仓库 `release/` 目录获取对应平台的预编译产物即可部署。
> 目录按 `<程序>/<版本>/<系统-架构>/` 组织，二进制文件名即为程序名（不带版本、架构与扩展名，版本与架构信息由目录体现）。

### 目录结构

```
release/
├── seeinpm/
│   └── <版本>/linux-amd64/
│       ├── seeinpm              # 中心端二进制
│       └── conf/seeinpm.toml    # 配置模板
├── seeinps/
│   └── <版本>/
│       ├── linux-amd64/
│       │   ├── seeinps          # 服务端二进制（Linux）
│       │   └── conf/seeinps.toml
│       └── windows-amd64/
│           ├── seeinps.exe      # 服务端二进制（Windows）
│           └── conf/seeinps.toml
├── seeinpc/
│   └── <版本>/                  # 客户端（待提供）
└── seeinps-deployer/
    └── <版本>/
        └── seeinps-deployer.exe # 部署工具（Windows）
```

### 二进制文件名说明

| 端 | 二进制文件名 | 所在目录 | 说明 |
|----|--------------|----------|------|
| seeinpm 中心端 | `seeinpm` | `release/seeinpm/<版本>/linux-amd64/` | 仅 Linux amd64 |
| seeinps 服务端 | `seeinps` / `seeinps.exe` | `release/seeinps/<版本>/linux-amd64/`、`windows-amd64/` | Linux amd64 / Windows amd64 |
| seeinpc 客户端 | `seeinpc` | `release/seeinpc/<版本>/windows-amd64/` | 仅 Windows amd64（待提供） |
| 部署工具 | `seeinps-deployer.exe` | `release/seeinps-deployer/<版本>/` | 仅 Windows，用于远程部署 seeinps |

> **重要**：
> - 发布产物内所有二进制统一以程序名命名，**不带版本号、架构等信息**（版本与架构信息由目录路径体现）。
> - Windows 平台产物带 `.exe` 后缀（`seeinps.exe` / `seeinps-deployer.exe`），Linux 平台无后缀（`seeinpm` / `seeinps`）。

### 快速开始

1. 根据部署目标从 `release/` 选取对应 `<程序>/<版本>/<系统-架构>/` 目录
2. 将该目录下的二进制（连同 `conf/` 配置模板）上传到目标服务器
3. 按本文档第 4/5/6 章的步骤完成各端（seeinpm / seeinps / seeinpc）的独立配置与启动

> 三端相互独立，可分别部署在不同机器上，按 seeinpm → seeinps → seeinpc 的顺序依次上线。

## 1. 系统架构概览

```
┌──────────────────────────────────────────────────────────┐
│                    seeinpm 中心端（Linux amd64）           │
│  端口 999：B端 Web + REST API + WebSocket + 控制通道        │
│  端口池 20000-30000：对外映射端口（TCP + UDP）              │
└─────────▲────────────────────────────▲───────────────────┘
          │ TLS + mux 控制通道           │ TCP/UDP 数据流
          │                              │
┌─────────┴──────────┐         ┌────────┴──────────────────┐
│  seeinps 服务端     │         │   外部访问者               │
│  (Linux/Windows)   │◄────────┤   (浏览器/SSH/工具)        │
│  端口 65443：B端+API│  转发   │                           │
└────────────────────┘         └───────────────────────────┘
          ▲
          │ SOCKS5/HTTP 代理（运维端口）
          │
┌─────────┴──────────┐
│  seeinpc 客户端     │
│  (Windows)         │
│  端口 65444：本地API │
│  端口 1080：SOCKS5  │
└────────────────────┘
```

**三端关系：**
- **seeinpm**：中央枢纽，管理用户/授权码/端口池，对外暴露映射端口
- **seeinps**：部署在被访问的内网服务器，主动外连 seeinpm，接收转发流量
- **seeinpc**：安装在运维人员电脑，通过 seeinpm 的运维代理访问内网（VPN 体验）

## 2. 环境依赖

### 2.1 构建环境（开发机）

| 依赖 | 最低版本 | 用途 | 下载地址 |
|------|----------|------|----------|
| Go | 1.22+（推荐 1.26+） | 编译三端二进制 | https://go.dev/dl/ |
| Node.js | 18+（推荐 20 LTS） | 构建前端 | https://nodejs.org/ |
| npm | 9+ | 前端依赖管理 | 随 Node.js 安装 |
| Git | 2.20+ | 获取源码 | https://git-scm.com/ |

### 2.2 运行环境

| 端 | 操作系统 | 架构 | 额外依赖 |
|----|----------|------|----------|
| seeinpm | Linux | amd64（x86_64） | 无（纯 Go，零 CGO） |
| seeinps | Linux / Windows | amd64 | 无 |
| seeinpc | Windows | amd64 | 管理员权限（VPN 虚拟网卡需要） |

> **平台说明**：seeinpm 中心端仅支持 Linux amd64（x86_64）部署，二进制文件名为 `seeinpm`（无 `.exe` 后缀）。

> **零 CGO 依赖**：使用 `modernc.org/sqlite`（纯 Go SQLite 驱动），无需安装 C 编译器或 SQLite 库。

### 2.3 网络端口规划

| 端 | 默认端口 | 协议 | 用途 | 是否对外 |
|----|----------|------|------|----------|
| seeinpm | 90 | TCP | B端 Web + API（同源） | 是（管理端与 deployer 访问） |
| seeinpm | 99 | TCP | 信令/控制通道（TLS，seeinps/seeinpc 拨入） | 是（seeinps 和 seeinpc 需访问） |
| seeinpm | 20000-30000 | TCP + UDP | 端口池（对外映射） | 是（外部访问者连接） |
| seeinps | 65443 | TCP | B端 Web + API | 否（仅本地/内网管理） |
| seeinpc | 65444 | TCP | 本地 API | 否（仅本机） |
| seeinpc | 1080 | TCP | SOCKS5 代理 | 否（仅本机） |

> **端口映射协议说明**：seeinpm 端口池（20000-30000）已同时支持 **TCP 和 UDP** 端口转发。
> - **TCP 转发**：用于 HTTP/HTTPS/SSH/RDP 等基于 TCP 的服务
> - **UDP 转发**：用于 DNS、QUIC、游戏、音视频等基于 UDP 的服务
> - 创建端口映射时由 seeinps 上报目标协议类型，seeinpm 自动在对应协议上监听并转发
> - 防火墙需同时放行端口池的 TCP 和 UDP 端口

## 3. 源码构建

### 3.1 获取源码

```bash
git clone <仓库地址> seeinp
cd seeinp
```

### 3.2 构建发布产物

前端为 Vue 3 单页应用（`web-pm/` 为 seeinpm 管理端、`web-ps/` 为 seeinps B 端），构建后通过 `go:embed`（`internal/webui`）**直接嵌入二进制**——版本包自包含，升级二进制即同步更新前端，无需单独部署前端目录。

```bash
bash build/build.sh 1.0.26.0830.14              # 构建 seeinpm + seeinps（linux-amd64）
bash build/build.sh 1.0.26.0830.14 seeinps      # 仅构建 seeinps
ARCH=arm64 bash build/build.sh 1.0.26.0830.14   # 指定 GOARCH（默认 amd64）
```

该脚本会自动：构建 web-pm/web-ps 前端 → 拷贝到 `internal/webui/{pm,ps}/files/` → 交叉编译注入版本号的二进制 → 连同 `conf/<程序>.toml` 配置模板输出到 `release/<程序>/<版本>/<系统-架构>/`。前端未构建时二进制可编译，访问时显示"前端未构建"占位页。

```bash
WIN=1 bash build/build.sh 1.0.26.0830.14        # 额外产出 Windows 测试二进制 → test/e2e/runtime/（仅本地 e2e 测试用）
```

### 3.3 构建 seeinps-deployer（Windows）

```bash
bash build/build-deployer.sh 1.0.26.0830.14
```

产物输出到 `release/seeinps-deployer/<版本>/seeinps-deployer.exe`（发布版本号沿用 seeinps 当前版本）。

### 3.4 手动编译（可选）

一般情况直接使用 `build/build.sh`；需要手动编译时参照其输出布局：

```bash
VERSION="1.0.26.0830.14"
BUILD_TIME=$(date -u +%Y-%m-%dT%H:%M:%SZ)
LDFLAGS="-X github.com/seeinp/seeinp/internal/version.Version=${VERSION} \
         -X github.com/seeinp/seeinp/internal/version.Banner=seeinp-version:${VERSION} \
         -X github.com/seeinp/seeinp/internal/version.BuildTime=${BUILD_TIME}"

# seeinpm（Linux amd64）
GOOS=linux GOARCH=amd64 CGO_ENABLED=0 go build -ldflags "${LDFLAGS}" -o release/seeinpm/${VERSION}/linux-amd64/seeinpm ./cmd/seeinpm

# seeinps（Linux amd64）
GOOS=linux GOARCH=amd64 CGO_ENABLED=0 go build -ldflags "${LDFLAGS}" -o release/seeinps/${VERSION}/linux-amd64/seeinps ./cmd/seeinps
```

> 版本号务必经 `-ldflags` 注入：二进制内带有 `seeinp-version:<版本>` 标识，seeinpm 版本管理与自动升级依赖该标识识别包内版本。

产物统一输出到 `release/<程序>/<版本>/<系统-架构>/`，二进制文件名即为程序名（不带版本/架构/扩展名），并附带 `conf/<程序>.toml` 配置模板。

> seeinpm 仅构建 Linux amd64；seeinps 构建 Linux amd64 和 Windows amd64（Windows 产物经 `GOOS=windows go build` 得到，带 `.exe` 后缀）；seeinpc 仅构建 Windows amd64（待提供）。

## 4. seeinpm 中心端部署

### 4.1 部署平台

- **操作系统**：Linux（推荐 Ubuntu 22.04 / CentOS 8+ / Debian 12+）
- **架构**：amd64（x86_64）
- **公网 IP**：需有公网 IP 或域名，seeinps 和 seeinpc 需能访问

> seeinpm 仅提供 Linux amd64 预编译产物，位于 `release/seeinpm/<版本>/linux-amd64/`（二进制 `seeinpm` + `conf/seeinpm.toml`）。

### 4.2 安装步骤

#### 步骤 1：创建运行用户和目录

```bash
sudo useradd -r -m -d /opt/seeinpm -s /usr/sbin/nologin seeinpm
sudo mkdir -p /opt/seeinpm/{conf,data,logs}
sudo chown -R seeinpm:seeinpm /opt/seeinpm
```

#### 步骤 2：上传二进制

从 `release/seeinpm/<版本>/linux-amd64/` 取得 `seeinpm` 二进制（Linux amd64）：

```bash
# 将 seeinpm 二进制上传到服务器
scp seeinpm user@server:/tmp/
sudo mv /tmp/seeinpm /opt/seeinpm/seeinpm
sudo chmod +x /opt/seeinpm/seeinpm
```

#### 步骤 3：创建配置文件

```bash
sudo tee /opt/seeinpm/conf/seeinpm.toml > /dev/null << 'EOF'
[server]
addr = ":99"        # 信令/控制通道监听（TLS）
http_addr = ":90"   # B端 Web + API 监听

[tls]
enabled = true
cert_file = ""  # 留空 = 自动生成自签证书（存于 data/）；自定义证书时填路径
key_file = ""   # 如 conf/server.key

[database]
path = "data/seeinpm.db"

[logging]
level = "info"
path = "logs"
max_size = 100
max_backups = 7

[port_pool]
# 端口池范围，必须确保这些端口未被占用且防火墙已放行
# 端口池同时支持 TCP 和 UDP 端口映射，防火墙需放行 TCP+UDP
ranges = [{start = 20000, end = 30000}]
excluded = []

[auth]
jwt_expire = 1800
jwt_refresh_expire = 86400
# 生产环境必须修改为随机 32 字节字符串（留空则自动生成）
jwt_secret = "请替换为随机32字节密钥"
EOF
```

生成随机 JWT 密钥：

```bash
openssl rand -hex 32
```

#### 步骤 4：配置 TLS 证书

```bash
# 方式一：使用 Let's Encrypt（推荐，需域名）
sudo apt install certbot
sudo certbot certonly --standalone -d see.yourdomain.com
sudo cp /etc/letsencrypt/live/see.yourdomain.com/fullchain.pem /opt/seeinpm/conf/server.crt
sudo cp /etc/letsencrypt/live/see.yourdomain.com/privkey.pem /opt/seeinpm/conf/server.key

# 方式二：自签证书（仅测试）
cd /opt/seeinpm/conf
openssl req -x509 -newkey rsa:2048 -keyout server.key -out server.crt -days 365 -nodes -subj "/CN=see.yourdomain.com"
```

#### 步骤 5：创建 systemd 服务

```bash
sudo tee /etc/systemd/system/seeinpm.service > /dev/null << 'EOF'
[Unit]
Description=seeinpm Central Server
After=network.target

[Service]
Type=simple
User=seeinpm
Group=seeinpm
WorkingDirectory=/opt/seeinpm
ExecStart=/opt/seeinpm/seeinpm -conf /opt/seeinpm/conf/seeinpm.toml
Restart=always
RestartSec=5
LimitNOFILE=65536

# 日志输出到 journald
StandardOutput=journal
StandardError=journal
SyslogIdentifier=seeinpm

[Install]
WantedBy=multi-user.target
EOF
```

#### 步骤 6：启动服务

```bash
sudo systemctl daemon-reload
sudo systemctl enable seeinpm
sudo systemctl start seeinpm
sudo systemctl status seeinpm
```

#### 步骤 7：验证

```bash
# 检查端口监听
ss -tlnp | grep -E ':(999|20000)'

# 测试 API
curl http://127.0.0.1:90/api/v1/version/check?endpoint=seeinps&current=0.1.0

# 查看日志
sudo journalctl -u seeinpm -f
```

#### 步骤 8：初始化管理员

首次启动后，调用初始化接口创建管理员账户：

```bash
curl -X POST http://127.0.0.1:90/api/v1/auth/init \
  -H "Content-Type: application/json" \
  -d '{"username":"admin","password":"YourStrongPassword123!"}'
```

> 密码强度要求：至少 8 位，包含大小写字母和数字。

#### 步骤 9：放行防火墙

```bash
# UFW（Ubuntu）
sudo ufw allow 90/tcp
sudo ufw allow 99/tcp
sudo ufw allow 20000:30000/tcp
sudo ufw allow 20000:30000/udp

# firewalld（CentOS）
sudo firewall-cmd --permanent --add-port=90/tcp
sudo firewall-cmd --permanent --add-port=99/tcp
sudo firewall-cmd --permanent --add-port=20000-30000/tcp
sudo firewall-cmd --permanent --add-port=20000-30000/udp
sudo firewall-cmd --reload
```

### 4.3 配置项详解

| 配置项 | 说明 | 默认值 | 必填 |
|--------|------|--------|------|
| `server.addr` | 信令/控制通道监听地址（TLS） | `:99` | 是 |
| `server.http_addr` | B端 Web + API 监听地址 | `:90` | 是 |
| `tls.enabled` | 是否启用 TLS | `true` | 是 |
| `tls.cert_file` / `tls.key_file` | TLS 证书/私钥路径，留空自动生成自签证书 | 空 | 否 |
| `database.path` | SQLite 数据库路径 | `data/seeinpm.db` | 是 |
| `logging.path` | 日志目录 | `logs` | 是 |
| `logging.level` | 日志级别（debug/info/warn/error） | `info` | 是 |
| `port_pool.ranges` | 端口池范围（同时支持 TCP 和 UDP 映射） | `20000-30000` | 是 |
| `auth.jwt_secret` | JWT 签名密钥（留空自动生成） | 空 | **必须修改** |
| `auth.jwt_expire` | Access Token 有效期（秒） | `1800` | 是 |
| `auth.jwt_refresh_expire` | Refresh Token 有效期（秒） | `86400` | 是 |

## 5. seeinps 服务端部署

### 5.1 部署平台

- **操作系统**：Linux 或 Windows
- **架构**：amd64
- **网络**：需能访问 seeinpm 的 99 端口（信令）

> seeinps 产物位于 `release/seeinps/<版本>/` 下，Linux 版在 `linux-amd64/`、Windows 版在 `windows-amd64/`，二进制统一命名为 `seeinps`（不带扩展名，版本与架构由目录体现）。

### 5.2 Linux 部署

#### 步骤 1：创建目录和用户

```bash
sudo useradd -r -m -d /opt/seeinps -s /usr/sbin/nologin seeinps
sudo mkdir -p /opt/seeinps/{conf,data,logs}
sudo chown -R seeinps:seeinps /opt/seeinps
```

#### 步骤 2：上传二进制

从 `release/seeinps/<版本>/linux-amd64/` 取得 `seeinps` 二进制（Linux amd64）：

```bash
scp seeinps user@server:/tmp/
sudo mv /tmp/seeinps /opt/seeinps/seeinps
sudo chmod +x /opt/seeinps/seeinps
```

#### 步骤 3：配置文件

```bash
sudo tee /opt/seeinps/conf/seeinps.toml > /dev/null << 'EOF'
[server]
# seeinpm 信令地址（公网 IP 或域名 + 99 信令端口）
server_addr = "see.yourdomain.com:99"

[auth]
# seeinpm 中为此 seeinps 创建的用户名与授权码
username = "site-a"
auth_code = "seeinp_由seeinpm管理员生成的授权码"

[tls]
enabled = true
skip_verify = true

[local]
# B端 Web + API 监听地址
bend_addr = ":65443"

[logging]
level = "info"
path = "logs"
max_size = 100
max_backups = 7
EOF
```

#### 步骤 4：填写授权码

授权码由 seeinpm 管理员在创建用户时生成，通过安全渠道分发，直接填入上方配置的 `[auth].auth_code` 字段（程序不读取独立的授权码文件）。

#### 步骤 5：创建 systemd 服务

```bash
sudo tee /etc/systemd/system/seeinps.service > /dev/null << 'EOF'
[Unit]
Description=seeinps Service Node
After=network.target

[Service]
Type=simple
User=seeinps
Group=seeinps
WorkingDirectory=/opt/seeinps
ExecStart=/opt/seeinps/seeinps -conf /opt/seeinps/conf/seeinps.toml
Restart=always
RestartSec=5
LimitNOFILE=65536

StandardOutput=journal
StandardError=journal
SyslogIdentifier=seeinps

[Install]
WantedBy=multi-user.target
EOF
```

#### 步骤 6：启动并验证

```bash
sudo systemctl daemon-reload
sudo systemctl enable seeinps
sudo systemctl start seeinps

# 验证连接状态
TOKEN=$(curl -s -X POST http://127.0.0.1:65443/api/v1/auth/login \
  -H "Content-Type: application/json" \
  -d '{"username":"admin","password":"YourPassword123!"}' | jq -r '.data.accessToken')

curl -s http://127.0.0.1:65443/api/v1/system/status \
  -H "Authorization: Bearer $TOKEN" | jq

# 预期：state=online，seeinpm 连接成功
```

### 5.3 Windows 部署

#### 步骤 1：创建目录

```powershell
New-Item -ItemType Directory -Force -Path C:\seeinps\conf,C:\seeinps\data,C:\seeinps\logs
```

#### 步骤 2：上传二进制和配置

从 `release/seeinps/<版本>/windows-amd64/` 取得 `seeinps.exe`，复制到 `C:\seeinps\seeinps.exe`，配置模板到 `C:\seeinps\conf\seeinps.toml`。

#### 步骤 3：注册为 Windows 服务

使用 NSSM（Non-Sucking Service Manager）：

```powershell
# 安装 NSSM
choco install nssm

# 注册服务
nssm install seeinps "C:\seeinps\seeinps.exe" "-conf" "C:\seeinps\conf\seeinps.toml"
nssm set seeinps AppDirectory "C:\seeinps"
nssm set seeinps AppStdout "C:\seeinps\logs\stdout.log"
nssm set seeinps AppStderr "C:\seeinps\logs\stderr.log"

# 启动
nssm start seeinps
```

### 5.4 使用 seeinps-deployer 远程部署

seeinps-deployer 是 Windows 上的 GUI 部署工具，可一键远程部署 seeinps（Linux amd64）。

从 `release/seeinps-deployer/<版本>/` 取得 `seeinps-deployer.exe`：

```powershell
# 运行部署工具
.\seeinps-deployer.exe
```

在界面中填写：
- 服务器 IP 和 SSH 端口
- SSH 用户名和密码
- 授权码（从 seeinpm 获取）
- 目标架构（linux-amd64）

工具会自动：SSH 连接 → 校验授权码 → 上传二进制和配置 → 安装 systemd 服务 → 启动服务。

## 6. seeinpc 客户端部署

### 6.1 部署平台

- **操作系统**：Windows 10/11（64 位，amd64）
- **权限**：管理员（VPN 虚拟网卡功能需要）

> seeinpc 仅支持 Windows amd64，二进制名为 `seeinpc`（产物位于 `release/seeinpc/<版本>/windows-amd64/`，待提供）。

### 6.2 安装步骤

#### 步骤 1：创建目录

```powershell
New-Item -ItemType Directory -Force -Path C:\seeinpc\conf,C:\seeinpc\logs
```

#### 步骤 2：上传二进制

从 `release/seeinpc/<版本>/windows-amd64/` 取得 `seeinpc`（待提供），复制为 `C:\seeinpc\seeinpc.exe`。

#### 步骤 3：配置文件

创建 `C:\seeinpc\conf\seeinpc.toml`：

```toml
[seeinpm]
# seeinpm 服务器地址
addr = "see.yourdomain.com:99"
tls_pinned_fingerprint = ""

[log]
dir = "logs"
level = "INFO"

# VPN profile 可通过 Web 界面管理，此处可留空
ignored_versions = []
```

#### 步骤 4：以管理员身份运行

**方式一：手动运行**

右键 `seeinpc.exe` → 以管理员身份运行。

**方式二：设置为开机自启**

```powershell
# 创建计划任务（开机以管理员身份启动）
$action = New-ScheduledTaskAction -Execute "C:\seeinpc\seeinpc.exe" -Argument "-conf C:\seeinpc\conf\seeinpc.toml"
$trigger = New-ScheduledTaskTrigger -AtLogon
$settings = New-ScheduledTaskSettingsSet -AllowStartIfOnBatteries -DontStopIfGoingOnBatteries -StartWhenAvailable
$principal = New-ScheduledTaskPrincipal -UserId "SYSTEM" -RunLevel Highest

Register-ScheduledTask -TaskName "seeinpc" -Action $action -Trigger $trigger -Settings $settings -Principal $principal
```

#### 步骤 5：验证

```powershell
# 检查状态
Invoke-RestMethod -Uri "http://127.0.0.1:65444/api/v1/status"

# 浏览器访问管理界面
start "http://127.0.0.1:65444/"
```

### 6.3 管理员权限说明

seeinpc 需要管理员权限的原因：
1. **虚拟网卡**：创建 wintun 虚拟网卡（ProxySwitch）需要驱动加载权限
2. **路由表**：修改系统路由表，将目标 CIDR 流量导向虚拟网卡
3. **系统代理**：设置系统级 SOCKS5/HTTP 代理

如仅使用 SOCKS5 代理模式（不启用 VPN 虚拟网卡），可以普通用户运行。

## 7. TLS 证书配置

### 7.1 生产环境（必须）

seeinpm 作为公网服务，**必须**配置 TLS 证书。

#### Let's Encrypt（推荐）

```bash
# 安装 certbot
sudo apt install certbot

# 申请证书（需先停止 80 端口服务）
sudo certbot certonly --standalone -d see.yourdomain.com

# 证书位置
# 证书：/etc/letsencrypt/live/see.yourdomain.com/fullchain.pem
# 私钥：/etc/letsencrypt/live/see.yourdomain.com/privkey.pem
```

在 `seeinpm.toml` 中配置：

```toml
[server]
tls_cert = "conf/server.crt"
tls_key = "conf/server.key"
```

#### 证书自动续期

```bash
# 添加 cron 任务
sudo crontab -e
# 每月 1 日凌晨 3 点续期
0 3 1 * * certbot renew --quiet && cp /etc/letsencrypt/live/see.yourdomain.com/fullchain.pem /opt/seeinpm/conf/server.crt && cp /etc/letsencrypt/live/see.yourdomain.com/privkey.pem /opt/seeinpm/conf/server.key && systemctl restart seeinpm
```

### 7.2 证书指纹固定（Pinning）

为防止中间人攻击，seeinps 和 seeinpc 可配置 TLS 证书指纹固定：

```bash
# 获取证书指纹
echo | openssl s_client -connect see.yourdomain.com:99 2>/dev/null | openssl x509 -fingerprint -sha256 -noout
# 输出：sha256 Fingerprint=AB:CD:EF:...

# 填入配置（去除冒号和前缀）
```

```toml
# seeinps.toml
[seeinpm]
tls_pinned_fingerprint = "ABCDEF1234567890..."
```

### 7.3 开发环境（跳过 TLS）

当 seeinpm 地址为 `127.0.0.1` 或 `localhost` 且未配置指纹时，seeinps 自动跳过 TLS 握手，使用明文 TCP。

> **警告**：此机制仅用于本地开发测试，生产环境必须使用 TLS。

## 8. 升级流程

### 8.1 seeinpm 升级

```bash
# 1. 下载新版本二进制
sudo systemctl stop seeinpm
sudo mv /opt/seeinpm/seeinpm /opt/seeinpm/seeinpm.bak
sudo cp /tmp/seeinpm-new /opt/seeinpm/seeinpm
sudo chmod +x /opt/seeinpm/seeinpm
sudo systemctl start seeinpm

# 2. 验证
sudo systemctl status seeinpm
curl http://127.0.0.1:90/api/v1/system/health -H "Authorization: Bearer $TOKEN"
```

### 8.2 seeinps 升级

#### 方式一：手动升级

```bash
sudo systemctl stop seeinps
sudo mv /opt/seeinps/seeinps /opt/seeinps/seeinps.bak
sudo cp /tmp/seeinps-new /opt/seeinps/seeinps
sudo chmod +x /opt/seeinps/seeinps
sudo systemctl start seeinps
```

#### 方式二：通过 seeinpm 批量升级

1. 在 seeinpm 管理界面上传新版本包（`版本管理` → `上传`）
2. 选择目标 seeinps 节点
3. 点击 `批量升级`
4. seeinpm 通过控制通道通知 seeinps 优雅停机
5. seeinps 下载新版本并自动重启

### 8.3 seeinpc 自动升级

seeinpc 内置自动升级机制：

1. 启动时检查 seeinpm 是否有新版本
2. 用户确认升级后，下载新版本到临时目录
3. 启动 `seeinpc-updater`，退出主程序
4. upgrader 替换二进制文件
5. 提示"升级成功"，用户点击确定
6. upgrader 重新启动 seeinpc 主程序

用户可在配置中忽略特定版本：

```toml
ignored_versions = ["0.2.0"]  # 不提示 0.2.0 版本升级
```

## 9. 故障排查

### 9.1 常见问题

#### seeinps 无法连接 seeinpm

```bash
# 1. 检查网络连通性
telnet see.yourdomain.com 999

# 2. 检查 seeinps 日志
sudo journalctl -u seeinps -f --since "5 minutes ago"

# 3. 常见原因
# - TLS 证书不匹配 → 检查 tls_pinned_fingerprint 或留空
# - 授权码错误 → 在 seeinpm 管理界面重置授权码
# - 防火墙拦截 → 放行 99（信令）和 90（B端）端口
# - 版本不兼容 → 检查 seeinpm 和 seeinps 版本
```

#### 端口映射无法访问

```bash
# 1. 检查 seeinpm 端口监听（TCP 和 UDP 均需检查）
ss -tlnp | grep <端口号>          # TCP 监听
ss -ulnp | grep <端口号>          # UDP 监听

# 2. 检查防火墙（确认 TCP 和 UDP 均已放行）
sudo ufw status
sudo iptables -L -n | grep <端口号>

# 3. 检查 seeinps 本地代理目标是否可达
# 在 seeinps 服务器上测试本地目标
curl http://127.0.0.1:<本地端口>/

# 4. 检查 seeinpm 代理列表
curl http://127.0.0.1:90/api/v1/proxies -H "Authorization: Bearer $TOKEN"
# 确认 seeinpsOnline=true，并核对映射协议（TCP/UDP）与目标一致
```

> **UDP 映射排查要点**：UDP 为无连接协议，`ss -ulnp` 可查看监听状态但无法像 TCP 那样验证连通性。若 UDP 映射不通，请检查：① 防火墙是否放行 UDP 端口；② seeinps 本地目标服务是否监听 UDP；③ 映射创建时协议是否选为 UDP。

#### seeinpc VPN 连接失败

```powershell
# 1. 检查 seeinpc ״̬
Invoke-RestMethod -Uri "http://127.0.0.1:65444/api/v1/status"

# 2. 检查是否以管理员身份运行
whoami /groups | findstr "S-1-16-12288"
# 无输出表示非管理员

# 3. 检查 seeinpm 连通性
Test-NetConnection see.yourdomain.com -Port 999

# 4. 查看日志
Get-Content C:\seeinpc\logs\seeinpc-*.log -Tail 50
```

### 9.2 日志位置

| 端 | 日志路径 | 查看命令 |
|----|----------|----------|
| seeinpm | `/opt/seeinpm/logs/seeinpm-YYYY-MM-DD.log` | `sudo journalctl -u seeinpm -f` |
| seeinps | `/opt/seeinps/logs/seeinps-YYYY-MM-DD.log` | `sudo journalctl -u seeinps -f` |
| seeinpc | `C:\seeinpc\logs\seeinpc-YYYY-MM-DD.log` | `Get-Content C:\seeinpc\logs\*.log -Tail 50` |

### 9.3 数据备份

```bash
# seeinpm 数据备份
sudo systemctl stop seeinpm
sudo tar -czf /tmp/seeinpm-backup-$(date +%Y%m%d).tar.gz -C /opt/seeinpm data/ conf/
sudo systemctl start seeinpm

# seeinps 数据备份
sudo systemctl stop seeinps
sudo tar -czf /tmp/seeinps-backup-$(date +%Y%m%d).tar.gz -C /opt/seeinps data/ conf/
sudo systemctl start seeinps
```
