# seeinp 部署文档

> 本文档详细说明 seeinp 三端（seeinpm 中心端 / seeinps 服务端 / seeinpc 客户端）的独立安装、配置与运行步骤。
> 适用于 v0.1.0 及以上版本。

---

## 最终成果物下载

> 无需自行编译源码，直接从 `release/packages/` 目录获取对应平台的预编译 zip 包即可部署。

### 可用成果物

| 成果物包 | 适用平台 | 用途 | 包含内容 |
|----------|----------|------|----------|
| `seeinpm-0.1.0-linux-amd64.zip` | Linux amd64 | seeinpm 中心端 | `seeinpm` 二进制 + 配置示例 |
| `seeinps-0.1.0-linux-amd64-manual.zip` | Linux amd64 | seeinps 服务端（手动部署） | `seeinps` 二进制 + 配置示例 |
| `seeinps-0.1.0-deployer-windows.zip` | Windows amd64 | seeinps 远程部署工具 | `seeinps-deployer.exe` + `seeinps` 二进制 |
| `seeinpc-0.1.0-windows-amd64.zip` | Windows amd64 | seeinpc 客户端 | `seeinpc.exe` + 配置示例 |

### 二进制文件名说明

| 端 | Linux 文件名 | Windows 文件名 | 说明 |
|----|--------------|----------------|------|
| seeinpm 中心端 | `seeinpm` | —（不支持 Windows） | 仅 Linux amd64，无 `.exe` 后缀 |
| seeinps 服务端 | `seeinps` | `seeinps.exe` | Linux amd64 / Windows amd64 |
| seeinpc 客户端 | —（不支持 Linux） | `seeinpc.exe` | 仅 Windows amd64 |
| 部署工具 | — | `seeinps-deployer.exe` | 仅 Windows，用于远程部署 seeinps |

> **重要**：
> - seeinpm 仅支持 Linux amd64 部署，二进制文件名为 `seeinpm`（**无 `.exe` 后缀**，因为是 Linux）。
> - seeinps 在 Linux 上为 `seeinps`（无后缀），在 Windows 上为 `seeinps.exe`。
> - seeinpc 仅 Windows，文件名为 `seeinpc.exe`。

### 快速开始

1. 根据部署目标从 `release/packages/` 选取对应 zip 包
2. 将 zip 包上传到目标服务器并解压
3. 按本文档第 4/5/6 章的步骤完成各端（seeinpm / seeinps / seeinpc）的独立配置与启动

> 三端相互独立，可分别部署在不同机器上，按 seeinpm → seeinps → seeinpc 的顺序依次上线。

## 1. 系统架构概览

```
┌──────────────────────────────────────────────────────────┐
│                    seeinpm 中心端（Linux amd64）           │
│  端口 999：B端 Web + REST API + WebSocket + 控制通道        │
│  端口池 20000-29999：对外映射端口（TCP + UDP）              │
└─────────▲────────────────────────────▲───────────────────┘
          │ TLS + mux 控制通道           │ TCP/UDP 数据流
          │                              │
┌─────────┴──────────┐         ┌────────┴──────────────────┐
│  seeinps 服务端     │         │   外部访问者               │
│  (Linux/Windows)   │◄────────┤   (浏览器/SSH/工具)        │
│  端口 65443：B端+API│  转发   │                           │
└────────────────────┘         └───────────────────────────┘
          ▲
          │ SOCKS5/HTTP 代理（运维端口）
          │
┌─────────┴──────────┐
│  seeinpc 客户端     │
│  (Windows)         │
│  端口 65444：本地API │
│  端口 1080：SOCKS5  │
└────────────────────┘
```

**三端关系：**
- **seeinpm**：中央枢纽，管理用户/授权码/端口池，对外暴露映射端口
- **seeinps**：部署在被访问的内网服务器，主动外连 seeinpm，接收转发流量
- **seeinpc**：安装在运维人员电脑，通过 seeinpm 的运维代理访问内网（VPN 体验）

## 2. 环境依赖

### 2.1 构建环境（开发机）

| 依赖 | 最低版本 | 用途 | 下载地址 |
|------|----------|------|----------|
| Go | 1.22+（推荐 1.26+） | 编译三端二进制 | https://go.dev/dl/ |
| Node.js | 18+（推荐 20 LTS） | 构建前端 | https://nodejs.org/ |
| npm | 9+ | 前端依赖管理 | 随 Node.js 安装 |
| Git | 2.20+ | 获取源码 | https://git-scm.com/ |

### 2.2 运行环境

| 端 | 操作系统 | 架构 | 额外依赖 |
|----|----------|------|----------|
| seeinpm | Linux | amd64（x86_64） | 无（纯 Go，零 CGO） |
| seeinps | Linux / Windows | amd64 | 无 |
| seeinpc | Windows | amd64 | 管理员权限（VPN 虚拟网卡需要） |

> **平台说明**：seeinpm 中心端仅支持 Linux amd64（x86_64）部署，二进制文件名为 `seeinpm`（无 `.exe` 后缀）。

> **零 CGO 依赖**：使用 `modernc.org/sqlite`（纯 Go SQLite 驱动），无需安装 C 编译器或 SQLite 库。

### 2.3 网络端口规划

| 端 | 默认端口 | 协议 | 用途 | 是否对外 |
|----|----------|------|------|----------|
| seeinpm | 999 | TCP | Web + API + 控制通道 | 是（seeinps 和 seeinpc 需访问） |
| seeinpm | 20000-29999 | TCP + UDP | 端口池（对外映射） | 是（外部访问者连接） |
| seeinps | 65443 | TCP | Web + API | 否（仅本地管理） |
| seeinpc | 65444 | TCP | 本地 API | 否（仅本机） |
| seeinpc | 1080 | TCP | SOCKS5 代理 | 否（仅本机） |

> **端口映射协议说明**：seeinpm 端口池（20000-29999）已同时支持 **TCP 和 UDP** 端口转发。
> - **TCP 转发**：用于 HTTP/HTTPS/SSH/RDP 等基于 TCP 的服务
> - **UDP 转发**：用于 DNS、QUIC、游戏、音视频等基于 UDP 的服务
> - 创建端口映射时由 seeinps 上报目标协议类型，seeinpm 自动在对应协议上监听并转发
> - 防火墙需同时放行端口池的 TCP 和 UDP 端口

## 3. 源码构建

### 3.1 获取源码

```bash
git clone <仓库地址> seeinp
cd seeinp
```

### 3.2 构建前端

前端为 Vue 3 单页应用（`web-pm/` 为 seeinpm 管理端、`web-ps/` 为 seeinps B 端），构建后通过 `go:embed`（`internal/webui`）**直接嵌入二进制**——版本包自包含，升级二进制即同步更新前端，无需单独部署前端目录。

```bash
bash scripts/build.sh 1.0.26.0829.03
```

该脚本会自动：构建 web-pm/web-ps 前端 → 拷贝到 `internal/webui/{pm,ps}/files/` → 交叉编译注入版本号的 linux-amd64 二进制。前端未构建时二进制可编译，访问时显示"前端未构建"占位页。

### 3.3 编译三端二进制

使用 Makefile（推荐）：

```bash
# 构建全部（当前平台）
make build

# 或单独构建
make build-pm      # seeinpm（Linux amd64）
make build-ps      # seeinps
make build-pc      # seeinpc（Windows amd64）
make build-deployer  # seeinps-deployer（Windows）
```

或手动编译：

```bash
# 版本信息注入
VERSION="0.1.0"
BUILD_TIME=$(date -u +%Y-%m-%dT%H:%M:%SZ)
LDFLAGS="-X github.com/seeinp/seeinp/internal/version.Version=${VERSION} \
         -X github.com/seeinp/seeinp/internal/version.BuildTime=${BUILD_TIME}"

# seeinpm（Linux amd64，无 .exe 后缀）
GOOS=linux GOARCH=amd64 go build -ldflags "${LDFLAGS}" -o dist/seeinpm ./cmd/seeinpm

# seeinps（Linux amd64）
GOOS=linux GOARCH=amd64 go build -ldflags "${LDFLAGS}" -o dist/seeinps ./cmd/seeinps

# seeinpc（Windows amd64）
GOOS=windows GOARCH=amd64 go build -ldflags "${LDFLAGS}" -o dist/seeinpc.exe ./cmd/seeinpc
```

### 3.4 交叉编译 Release 包

```bash
# ȫƽ̨ release
make release

# 或单独
make release-pm   # seeinpm: linux-amd64
make release-ps   # seeinps: linux-amd64, windows-amd64
make release-pc   # seeinpc: windows-amd64
```

产物输出到 `dist/` 目录，最终打包到 `release/packages/`，命名格式：`{端}-{版本}-{os}-{arch}[.exe].zip`

> seeinpm 仅构建 Linux amd64 包；seeinps 构建 Linux amd64 和 Windows amd64 包；seeinpc 仅构建 Windows amd64 包。

## 4. seeinpm 中心端部署

### 4.1 部署平台

- **操作系统**：Linux（推荐 Ubuntu 22.04 / CentOS 8+ / Debian 12+）
- **架构**：amd64（x86_64）
- **公网 IP**：需有公网 IP 或域名，seeinps 和 seeinpc 需能访问

> seeinpm 仅提供 Linux amd64 预编译包（`seeinpm-0.1.0-linux-amd64.zip`），二进制文件名为 `seeinpm`（无 `.exe` 后缀）。

### 4.2 安装步骤

#### 步骤 1：创建运行用户和目录

```bash
sudo useradd -r -m -d /opt/seeinpm -s /usr/sbin/nologin seeinpm
sudo mkdir -p /opt/seeinpm/{conf,data,logs}
sudo chown -R seeinpm:seeinpm /opt/seeinpm
```

#### 步骤 2：上传二进制

从 `release/packages/seeinpm-0.1.0-linux-amd64.zip` 解压得到 `seeinpm` 二进制（无 `.exe` 后缀，Linux amd64）：

```bash
# 将 seeinpm 二进制上传到服务器
scp seeinpm user@server:/tmp/
sudo mv /tmp/seeinpm /opt/seeinpm/seeinpm
sudo chmod +x /opt/seeinpm/seeinpm
```

#### 步骤 3：创建配置文件

```bash
sudo tee /opt/seeinpm/conf/seeinpm.toml > /dev/null << 'EOF'
[server]
listen = ":999"
# 生产环境必须配置 TLS
tls_cert = "conf/server.crt"
tls_key = "conf/server.key"

[db]
path = "data/seeinpm.db"

[log]
dir = "logs"
level = "INFO"
max_bytes = 104857600
run_max_days = 30
access_max_days = 90
audit_max_days = 365

[port_pool]
# 端口池范围，必须确保这些端口未被占用且防火墙已放行
# 端口池同时支持 TCP 和 UDP 端口映射，防火墙需放行 TCP+UDP
ranges = [{start = 20000, end = 29999}]
excluded = []

[auth]
access_token_ttl = 1800
refresh_token_ttl = 86400
# 生产环境必须修改为随机 32 字节字符串
jwt_secret = "请替换为随机32字节密钥"

[release]
dir = "data/releases"
EOF
```

生成随机 JWT 密钥：

```bash
openssl rand -hex 32
```

#### 步骤 4：配置 TLS 证书

```bash
# 方式一：使用 Let's Encrypt（推荐，需域名）
sudo apt install certbot
sudo certbot certonly --standalone -d see.yourdomain.com
sudo cp /etc/letsencrypt/live/see.yourdomain.com/fullchain.pem /opt/seeinpm/conf/server.crt
sudo cp /etc/letsencrypt/live/see.yourdomain.com/privkey.pem /opt/seeinpm/conf/server.key

# 方式二：自签证书（仅测试）
cd /opt/seeinpm/conf
openssl req -x509 -newkey rsa:2048 -keyout server.key -out server.crt -days 365 -nodes -subj "/CN=see.yourdomain.com"
```

#### 步骤 5：创建 systemd 服务

```bash
sudo tee /etc/systemd/system/seeinpm.service > /dev/null << 'EOF'
[Unit]
Description=seeinpm Central Server
After=network.target

[Service]
Type=simple
User=seeinpm
Group=seeinpm
WorkingDirectory=/opt/seeinpm
ExecStart=/opt/seeinpm/seeinpm -conf /opt/seeinpm/conf/seeinpm.toml
Restart=always
RestartSec=5
LimitNOFILE=65536

# 日志输出到 journald
StandardOutput=journal
StandardError=journal
SyslogIdentifier=seeinpm

[Install]
WantedBy=multi-user.target
EOF
```

#### 步骤 6：启动服务

```bash
sudo systemctl daemon-reload
sudo systemctl enable seeinpm
sudo systemctl start seeinpm
sudo systemctl status seeinpm
```

#### 步骤 7：验证

```bash
# 检查端口监听
ss -tlnp | grep -E ':(999|20000)'

# 测试 API
curl http://127.0.0.1:999/api/v1/version/check?endpoint=seeinps&current=0.1.0

# 查看日志
sudo journalctl -u seeinpm -f
```

#### 步骤 8：初始化管理员

首次启动后，调用初始化接口创建管理员账户：

```bash
curl -X POST http://127.0.0.1:999/api/v1/auth/init \
  -H "Content-Type: application/json" \
  -d '{"username":"admin","password":"YourStrongPassword123!"}'
```

> 密码强度要求：至少 8 位，包含大小写字母和数字。

#### 步骤 9：放行防火墙

```bash
# UFW（Ubuntu）
sudo ufw allow 999/tcp
sudo ufw allow 20000:29999/tcp
sudo ufw allow 20000:29999/udp

# firewalld（CentOS）
sudo firewall-cmd --permanent --add-port=999/tcp
sudo firewall-cmd --permanent --add-port=20000-29999/tcp
sudo firewall-cmd --permanent --add-port=20000-29999/udp
sudo firewall-cmd --reload
```

### 4.3 配置项详解

| 配置项 | 说明 | 默认值 | 必填 |
|--------|------|--------|------|
| `server.listen` | 监听地址 | `:999` | 是 |
| `server.tls_cert` | TLS 证书路径 | 空 | 生产必填 |
| `server.tls_key` | TLS 私钥路径 | 空 | 生产必填 |
| `db.path` | SQLite 数据库路径 | `data/seeinpm.db` | 是 |
| `log.dir` | 日志目录 | `logs` | 是 |
| `log.level` | 日志级别（DEBUG/INFO/WARN/ERROR） | `INFO` | 是 |
| `port_pool.ranges` | 端口池范围（同时支持 TCP 和 UDP 映射） | `20000-29999` | 是 |
| `auth.jwt_secret` | JWT 签名密钥 | 空 | **必须修改** |
| `auth.access_token_ttl` | Access Token 有效期（秒） | `1800` | 是 |
| `auth.refresh_token_ttl` | Refresh Token 有效期（秒） | `86400` | 是 |
| `release.dir` | 版本包存储目录 | `data/releases` | 是 |

## 5. seeinps 服务端部署

### 5.1 部署平台

- **操作系统**：Linux 或 Windows
- **架构**：amd64
- **网络**：需能访问 seeinpm 的 999 端口

> seeinps 在 Linux 上文件名为 `seeinps`（无 `.exe` 后缀），在 Windows 上为 `seeinps.exe`。预编译包：`seeinps-0.1.0-linux-amd64-manual.zip`（Linux 手动部署）和 `seeinps-0.1.0-deployer-windows.zip`（含 Windows 部署工具）。

### 5.2 Linux 部署

#### 步骤 1：创建目录和用户

```bash
sudo useradd -r -m -d /opt/seeinps -s /usr/sbin/nologin seeinps
sudo mkdir -p /opt/seeinps/{conf,data,logs}
sudo chown -R seeinps:seeinps /opt/seeinps
```

#### 步骤 2：上传二进制

从 `release/packages/seeinps-0.1.0-linux-amd64-manual.zip` 解压得到 `seeinps` 二进制（无 `.exe` 后缀，Linux amd64）：

```bash
scp seeinps user@server:/tmp/
sudo mv /tmp/seeinps /opt/seeinps/seeinps
sudo chmod +x /opt/seeinps/seeinps
```

#### 步骤 3：配置文件

```bash
sudo tee /opt/seeinps/conf/seeinps.toml > /dev/null << 'EOF'
[server]
listen = "127.0.0.1:65443"

[seeinpm]
# seeinpm 服务器地址（公网 IP 或域名）
addr = "see.yourdomain.com:999"
# TLS 证书指纹（可选，用于证书固定，留空则使用标准 CA 验证）
tls_pinned_fingerprint = ""
# seeinpm 中为此 seeinps 创建的用户名
username = "site-a"
# 授权码文件路径
auth_code_file = "conf/authcode"

[db]
path = "data/seeinps.db"

[log]
dir = "logs"
level = "INFO"
max_bytes = 104857600
run_max_days = 30

[auth]
access_token_ttl = 1800
refresh_token_ttl = 86400
jwt_secret = "请替换为随机32字节密钥"
EOF
```

#### 步骤 4：写入授权码

授权码由 seeinpm 管理员在创建用户时生成，通过安全渠道分发。

```bash
# 将 seeinpm 生成的授权码写入文件
echo "由seeinpm管理员提供的授权码字符串" | sudo tee /opt/seeinps/conf/authcode
sudo chmod 600 /opt/seeinps/conf/authcode
sudo chown seeinps:seeinps /opt/seeinps/conf/authcode
```

#### 步骤 5：创建 systemd 服务

```bash
sudo tee /etc/systemd/system/seeinps.service > /dev/null << 'EOF'
[Unit]
Description=seeinps Service Node
After=network.target

[Service]
Type=simple
User=seeinps
Group=seeinps
WorkingDirectory=/opt/seeinps
ExecStart=/opt/seeinps/seeinps -conf /opt/seeinps/conf/seeinps.toml
Restart=always
RestartSec=5
LimitNOFILE=65536

StandardOutput=journal
StandardError=journal
SyslogIdentifier=seeinps

[Install]
WantedBy=multi-user.target
EOF
```

#### 步骤 6：启动并验证

```bash
sudo systemctl daemon-reload
sudo systemctl enable seeinps
sudo systemctl start seeinps

# 验证连接状态
TOKEN=$(curl -s -X POST http://127.0.0.1:65443/api/v1/auth/login \
  -H "Content-Type: application/json" \
  -d '{"username":"admin","password":"YourPassword123!"}' | jq -r '.data.accessToken')

curl -s http://127.0.0.1:65443/api/v1/system/status \
  -H "Authorization: Bearer $TOKEN" | jq

# 预期：state=online，seeinpm 连接成功
```

### 5.3 Windows 部署

#### 步骤 1：创建目录

```powershell
New-Item -ItemType Directory -Force -Path C:\seeinps\conf,C:\seeinps\data,C:\seeinps\logs
```

#### 步骤 2：上传二进制和配置

从 `release/packages/seeinps-0.1.0-deployer-windows.zip` 解压得到 `seeinps.exe`，复制到 `C:\seeinps\seeinps.exe`，配置文件到 `C:\seeinps\conf\seeinps.toml`。

#### 步骤 3：注册为 Windows 服务

使用 NSSM（Non-Sucking Service Manager）：

```powershell
# 安装 NSSM
choco install nssm

# 注册服务
nssm install seeinps "C:\seeinps\seeinps.exe" "-conf" "C:\seeinps\conf\seeinps.toml"
nssm set seeinps AppDirectory "C:\seeinps"
nssm set seeinps AppStdout "C:\seeinps\logs\stdout.log"
nssm set seeinps AppStderr "C:\seeinps\logs\stderr.log"

# 启动
nssm start seeinps
```

### 5.4 使用 seeinps-deployer 远程部署

seeinps-deployer 是 Windows 上的 GUI 部署工具，可一键远程部署 seeinps（Linux amd64）。

从 `release/packages/seeinps-0.1.0-deployer-windows.zip` 解压得到 `seeinps-deployer.exe`：

```powershell
# 运行部署工具
.\seeinps-deployer.exe
```

在界面中填写：
- 服务器 IP 和 SSH 端口
- SSH 用户名和密码
- 授权码（从 seeinpm 获取）
- 目标架构（linux-amd64）

工具会自动：SSH 连接 → 校验授权码 → 上传二进制和配置 → 安装 systemd 服务 → 启动服务。

## 6. seeinpc 客户端部署

### 6.1 部署平台

- **操作系统**：Windows 10/11（64 位，amd64）
- **权限**：管理员（VPN 虚拟网卡功能需要）

> seeinpc 仅支持 Windows amd64，文件名为 `seeinpc.exe`。预编译包：`seeinpc-0.1.0-windows-amd64.zip`。

### 6.2 安装步骤

#### 步骤 1：创建目录

```powershell
New-Item -ItemType Directory -Force -Path C:\seeinpc\conf,C:\seeinpc\logs
```

#### 步骤 2：上传二进制

从 `release/packages/seeinpc-0.1.0-windows-amd64.zip` 解压得到 `seeinpc.exe`，复制到 `C:\seeinpc\seeinpc.exe`。

#### 步骤 3：配置文件

创建 `C:\seeinpc\conf\seeinpc.toml`：

```toml
[seeinpm]
# seeinpm 服务器地址
addr = "see.yourdomain.com:999"
tls_pinned_fingerprint = ""

[log]
dir = "logs"
level = "INFO"

# VPN profile 可通过 Web 界面管理，此处可留空
ignored_versions = []
```

#### 步骤 4：以管理员身份运行

**方式一：手动运行**

右键 `seeinpc.exe` → 以管理员身份运行。

**方式二：设置为开机自启**

```powershell
# 创建计划任务（开机以管理员身份启动）
$action = New-ScheduledTaskAction -Execute "C:\seeinpc\seeinpc.exe" -Argument "-conf C:\seeinpc\conf\seeinpc.toml"
$trigger = New-ScheduledTaskTrigger -AtLogon
$settings = New-ScheduledTaskSettingsSet -AllowStartIfOnBatteries -DontStopIfGoingOnBatteries -StartWhenAvailable
$principal = New-ScheduledTaskPrincipal -UserId "SYSTEM" -RunLevel Highest

Register-ScheduledTask -TaskName "seeinpc" -Action $action -Trigger $trigger -Settings $settings -Principal $principal
```

#### 步骤 5：验证

```powershell
# 检查状态
Invoke-RestMethod -Uri "http://127.0.0.1:65444/api/v1/status"

# 浏览器访问管理界面
start "http://127.0.0.1:65444/"
```

### 6.3 管理员权限说明

seeinpc 需要管理员权限的原因：
1. **虚拟网卡**：创建 wintun 虚拟网卡（ProxySwitch）需要驱动加载权限
2. **路由表**：修改系统路由表，将目标 CIDR 流量导向虚拟网卡
3. **系统代理**：设置系统级 SOCKS5/HTTP 代理

如仅使用 SOCKS5 代理模式（不启用 VPN 虚拟网卡），可以普通用户运行。

## 7. TLS 证书配置

### 7.1 生产环境（必须）

seeinpm 作为公网服务，**必须**配置 TLS 证书。

#### Let's Encrypt（推荐）

```bash
# 安装 certbot
sudo apt install certbot

# 申请证书（需先停止 80 端口服务）
sudo certbot certonly --standalone -d see.yourdomain.com

# 证书位置
# 证书：/etc/letsencrypt/live/see.yourdomain.com/fullchain.pem
# 私钥：/etc/letsencrypt/live/see.yourdomain.com/privkey.pem
```

在 `seeinpm.toml` 中配置：

```toml
[server]
tls_cert = "conf/server.crt"
tls_key = "conf/server.key"
```

#### 证书自动续期

```bash
# 添加 cron 任务
sudo crontab -e
# 每月 1 日凌晨 3 点续期
0 3 1 * * certbot renew --quiet && cp /etc/letsencrypt/live/see.yourdomain.com/fullchain.pem /opt/seeinpm/conf/server.crt && cp /etc/letsencrypt/live/see.yourdomain.com/privkey.pem /opt/seeinpm/conf/server.key && systemctl restart seeinpm
```

### 7.2 证书指纹固定（Pinning）

为防止中间人攻击，seeinps 和 seeinpc 可配置 TLS 证书指纹固定：

```bash
# 获取证书指纹
echo | openssl s_client -connect see.yourdomain.com:999 2>/dev/null | openssl x509 -fingerprint -sha256 -noout
# 输出：sha256 Fingerprint=AB:CD:EF:...

# 填入配置（去除冒号和前缀）
```

```toml
# seeinps.toml
[seeinpm]
tls_pinned_fingerprint = "ABCDEF1234567890..."
```

### 7.3 开发环境（跳过 TLS）

当 seeinpm 地址为 `127.0.0.1` 或 `localhost` 且未配置指纹时，seeinps 自动跳过 TLS 握手，使用明文 TCP。

> **警告**：此机制仅用于本地开发测试，生产环境必须使用 TLS。

## 8. 升级流程

### 8.1 seeinpm 升级

```bash
# 1. 下载新版本二进制
sudo systemctl stop seeinpm
sudo mv /opt/seeinpm/seeinpm /opt/seeinpm/seeinpm.bak
sudo cp /tmp/seeinpm-new /opt/seeinpm/seeinpm
sudo chmod +x /opt/seeinpm/seeinpm
sudo systemctl start seeinpm

# 2. 验证
sudo systemctl status seeinpm
curl http://127.0.0.1:999/api/v1/system/health -H "Authorization: Bearer $TOKEN"
```

### 8.2 seeinps 升级

#### 方式一：手动升级

```bash
sudo systemctl stop seeinps
sudo mv /opt/seeinps/seeinps /opt/seeinps/seeinps.bak
sudo cp /tmp/seeinps-new /opt/seeinps/seeinps
sudo chmod +x /opt/seeinps/seeinps
sudo systemctl start seeinps
```

#### 方式二：通过 seeinpm 批量升级

1. 在 seeinpm 管理界面上传新版本包（`版本管理` → `上传`）
2. 选择目标 seeinps 节点
3. 点击 `批量升级`
4. seeinpm 通过控制通道通知 seeinps 优雅停机
5. seeinps 下载新版本并自动重启

### 8.3 seeinpc 自动升级

seeinpc 内置自动升级机制：

1. 启动时检查 seeinpm 是否有新版本
2. 用户确认升级后，下载新版本到临时目录
3. 启动 `seeinpc-updater`，退出主程序
4. upgrader 替换二进制文件
5. 提示"升级成功"，用户点击确定
6. upgrader 重新启动 seeinpc 主程序

用户可在配置中忽略特定版本：

```toml
ignored_versions = ["0.2.0"]  # 不提示 0.2.0 版本升级
```

## 9. 故障排查

### 9.1 常见问题

#### seeinps 无法连接 seeinpm

```bash
# 1. 检查网络连通性
telnet see.yourdomain.com 999

# 2. 检查 seeinps 日志
sudo journalctl -u seeinps -f --since "5 minutes ago"

# 3. 常见原因
# - TLS 证书不匹配 → 检查 tls_pinned_fingerprint 或留空
# - 授权码错误 → 在 seeinpm 管理界面重置授权码
# - 防火墙拦截 → 放行 999 端口
# - 版本不兼容 → 检查 seeinpm 和 seeinps 版本
```

#### 端口映射无法访问

```bash
# 1. 检查 seeinpm 端口监听（TCP 和 UDP 均需检查）
ss -tlnp | grep <端口号>          # TCP 监听
ss -ulnp | grep <端口号>          # UDP 监听

# 2. 检查防火墙（确认 TCP 和 UDP 均已放行）
sudo ufw status
sudo iptables -L -n | grep <端口号>

# 3. 检查 seeinps 本地代理目标是否可达
# 在 seeinps 服务器上测试本地目标
curl http://127.0.0.1:<本地端口>/

# 4. 检查 seeinpm 代理列表
curl http://127.0.0.1:999/api/v1/proxies -H "Authorization: Bearer $TOKEN"
# 确认 seeinpsOnline=true，并核对映射协议（TCP/UDP）与目标一致
```

> **UDP 映射排查要点**：UDP 为无连接协议，`ss -ulnp` 可查看监听状态但无法像 TCP 那样验证连通性。若 UDP 映射不通，请检查：① 防火墙是否放行 UDP 端口；② seeinps 本地目标服务是否监听 UDP；③ 映射创建时协议是否选为 UDP。

#### seeinpc VPN 连接失败

```powershell
# 1. 检查 seeinpc ״̬
Invoke-RestMethod -Uri "http://127.0.0.1:65444/api/v1/status"

# 2. 检查是否以管理员身份运行
whoami /groups | findstr "S-1-16-12288"
# 无输出表示非管理员

# 3. 检查 seeinpm 连通性
Test-NetConnection see.yourdomain.com -Port 999

# 4. 查看日志
Get-Content C:\seeinpc\logs\seeinpc-*.log -Tail 50
```

### 9.2 日志位置

| 端 | 日志路径 | 查看命令 |
|----|----------|----------|
| seeinpm | `/opt/seeinpm/logs/seeinpm-YYYY-MM-DD.log` | `sudo journalctl -u seeinpm -f` |
| seeinps | `/opt/seeinps/logs/seeinps-YYYY-MM-DD.log` | `sudo journalctl -u seeinps -f` |
| seeinpc | `C:\seeinpc\logs\seeinpc-YYYY-MM-DD.log` | `Get-Content C:\seeinpc\logs\*.log -Tail 50` |

### 9.3 数据备份

```bash
# seeinpm 数据备份
sudo systemctl stop seeinpm
sudo tar -czf /tmp/seeinpm-backup-$(date +%Y%m%d).tar.gz -C /opt/seeinpm data/ conf/
sudo systemctl start seeinpm
```
